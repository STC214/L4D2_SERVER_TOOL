# Feasibility Matrix

## 方案 A：纯 VPK 增加游戏内过滤选项

结论：可行性低。

原因：

- L4D2 addon 通常不能执行任意客户端代码。
- 服务器列表刷新、排序、加入、随机匹配大概率在客户端二进制和 Steamworks/Source 接口内完成。
- VPK 可以覆盖部分 UI 资源，但 UI 资源本身通常不具备“遍历服务器列表并按关键字删除项”的脚本能力。

适合继续验证的点：

- 是否存在可覆盖的服务器浏览器 `.res` 文件。
- 是否存在能绑定到过滤输入框的内置控件/命令。
- 是否有官方隐藏 cvar 或 launch option 能影响服务器列表过滤。

## 方案 B：VPK 内置配置文件 + Go/Win32 配置器

结论：最适合落地。

实现方式：

- VPK/loose addon 内放默认配置，例如 `cfg/l4d2_server_filter/keywords.txt`。
- Go + Win32 配置器负责编辑关键字、校验格式、备份旧配置。
- 外部工具读取同一份配置，负责观察服务器 IP、导出屏蔽列表、应用 Windows 防火墙。

优点：

- 不需要注入游戏。
- 可以保留创意工坊审核可能性。
- 和当前 Go 工具复用度高。
- IP 屏蔽仍然可靠，不依赖游戏 UI 是否显示。

限制：

- 不能保证游戏内列表本身不显示命中服务器。
- 如果 VPK 不能执行过滤逻辑，游戏内 UI 只能展示说明或提供入口提示。

## 方案 C：通过 Mod 扩展内置服务器浏览器筛选功能

结论：需要先做资源边界验证，可行性中低。

验证路径：

1. 找出游戏服务器浏览器相关资源文件。
2. 尝试 loose addon 覆盖对应 `.res`。
3. 观察是否能新增输入框、按钮、标签或绑定已有命令。
4. 如果只能改布局，不能改数据源，则退回方案 B。

可能成功的最小功能：

- 在服务器浏览器附近增加一个“过滤配置入口/提示区域”。
- 显示当前关键字配置路径。
- 显示“实际 IP 屏蔽由外部工具执行”的状态提示。

不应承诺的功能：

- 纯资源文件实时删除服务器行。
- 纯 VPK 阻止随机匹配连接到命中服务器 IP。

## 方案 D：Hook 游戏内列表刷新逻辑

结论：研究价值高，最终交付价值低。

Hook 可能能确认真实实现，但它与“可被 Steam 创意工坊审核的 VPK Mod”目标冲突。它只能作为离线研究手段，用于回答“纯 VPK 是否有机会”和“外部工具应该观察哪些网络/接口行为”。
