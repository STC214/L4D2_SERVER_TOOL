# Hook Research Plan

本文件只记录离线分析计划和问题清单，不放注入代码、不放绕过反作弊逻辑、不作为最终 Mod 交付物。

## 研究目的

1. 确认游戏内组服务器列表的数据来源。
2. 确认服务器列表显示前是否存在可被 VPK/UI 资源影响的过滤阶段。
3. 确认随机匹配是否复用同一批服务器候选，还是走独立 matchmaking 接口。
4. 反推外部工具应该继续观察哪些网络包和 A2S 信息。

## 只记录这些结果

- 模块名。
- 字符串线索。
- UI 资源文件名。
- 可疑接口名。
- 调用链文字描述。
- 观察到的数据字段。
- 是否存在无需注入即可利用的配置或资源入口。

## 不进入仓库的内容

- 注入器。
- Hook DLL。
- 内存 patch。
- 反调试、反检测、隐藏模块代码。
- VAC 规避方法。
- 可直接对游戏进程生效的二进制修改脚本。

## 优先观察点

1. `left4dead2\resource\ui` 下是否存在服务器浏览器相关 `.res`。
2. `left4dead2\scripts` 下是否存在 matchmaking 或 server browser 相关脚本。
3. 游戏启动参数、控制台命令、cvar 是否提供过滤能力。
4. Steam server browser 与 L4D2 组服务器列表是否共享实现。
5. 当前外部工具捕获到的 Steam master 包是否覆盖列表中全部候选服务器。

## 判定标准

如果找到资源文件或 cvar 能影响列表过滤，则优先做纯 VPK 验证。

如果只能通过二进制 Hook 才能删除列表项，则最终方案回到：

- VPK 提供配置和 UI 提示。
- 外部工具负责真实 IP 观察与屏蔽。
- Hook 结论只作为研究备注。
